==============================================================================
PART A -- analytic: which seed estimates the converged EMA better?
==============================================================================

A seeded EMA reproduces the converged EMA exactly, plus one decaying term:
    y_seed(n) - y*(n) = (1-alpha)^(n-t0) * (seed - y*(t0))
The decay factor depends on alpha only -- it is the SAME for both rules.
So the seeding question is entirely 'how big is (seed - y*(t0))?'.

Rule T (TradingView ta.ema / Tulip): seed = x[t0], t0 = first data bar.
Rule S (TA-Lib / R TTR):             seed = SMA(x[t0-p+1..t0]), t0 = bar p-1,
                                     summed sequentially, as TA_EMA does.

Rule T seeds p-1 bars earlier, so by rule S's first output bar its error has
already been damped by (1-alpha)^(p-1).  The 'common' column credits it with
exactly that head start: it is sd(e_S) / [ (1-alpha)^(p-1) * sd(e_T) ], the
ratio of the two rules' errors at the SAME bar.  Below 1 = TA-Lib wins.

Reading the table:
  * e_S/e_T < 1 under every process: the SMA seed is the better estimator
    of the converged EMA, by 3x-9x at the periods SMI uses.
  * 'common' is the honest head-to-head at the same bar index, with rule T
    given full credit for having started p-1 bars earlier.
  * 'trend bias' is EXACT, not statistical.  alpha = 2/(p+1) puts the EMA's
    centre of mass at (1-alpha)/alpha = (p-1)/2 bars back -- precisely the
    centre of mass of a p-bar SMA.  So on any locally linear stretch the SMA
    seed is unbiased to machine precision while the last-value seed is off
    by (p-1)/2 * slope.  The p-bar SMA is not an arbitrary convention: it is
    the seed that alpha = 2/(p+1) was matched to.
