# TypeScript backend

**Status:** the design of `ta_codegen`'s TypeScript backend, which generates the `ta-lib` npm package, unreleased. The public API is [typescript-api-design.md](typescript-api-design.md). Rows marked Ruled are the owner's; Adopted rows stand unless he reopens them.

## 1. Scope

- **What ships.** An npm package that `ta_codegen` generates as it generates the Java and C# libraries: for every function the batch tier, lookback, display shift and streaming tier, plus the metadata (abstract) API. Pure TypeScript compiled to standard ES modules, no runtime dependencies, for Node and any runtime that loads standard ESM. It is the `ta-lib/js` entry of the package and the fallback of its default entry, whose WASM engine is [wasm-backend.md](wasm-backend.md).
- **How it is gated.** As the other managed backends: a generated JSON-RPC server, driven by `ta_regtest --codegen` and `--xlang-hash`, matches the C library bit for bit on every call except one that reaches a transcendental function (D11).
- **What does not ship:** a native addon, a browser-specific bundle (standard ESM is the browser story), a CommonJS build, a single-precision (`TA_S_`) surface.

## 2. Decisions

| # | Decision | Choice | Why | Status |
|---|---|---|---|---|
| D1 | Implementation | Pure TypeScript compiled to JS, no native addon. The package's default entry puts a WASM engine in front of it ([wasm-backend.md](wasm-backend.md) W1, W2) | One artifact for every JS runtime, emitted by the managed-backend machinery | Ruled (owner, 2026-11-01); WASM engine ruled (owner, 2026-11-11) |
| D2 | npm name | `ta-lib`, one constant in the TS scaffolding emitter | Matches the Python and Rust package names | Ruled (owner, 2026-11-01) |
| D3 | Module format, min Node | ESM only, with no top-level await and no `node:` imports in the library. `exports` has `"."` and `"./metadata"`, each with `"types"` first and `"default"` last, and `"./package.json"`; `typesVersions` maps `metadata` for older resolvers. `"sideEffects": false`. `engines.node` is `>=22.12.0`; CI runs 22, 24 and 26, plus exactly the `engines` floor | Every supported Node line can `require()` an ESM-only package; the PR gate loads both entry points through `require` after compiling them, the nightly's tarball run does the same. One artifact means no dual-package hazard breaking `instanceof TALibError` | Adopted |
| D4 | TS compile target | `target` and `lib` ES2022, plus `strict`, `erasableSyntaxOnly`, `verbatimModuleSyntax`, `isolatedModules`, `declaration` and `stripInternal`. No `enum` or `namespace` (use `as const` objects). `noUncheckedIndexedAccess` off. `types: []` in the library tsconfig. `module` and `moduleResolution` `nodenext`; relative imports are spelled `./x.ts` with `rewriteRelativeImportExtensions`, so tsc emits `.js` and `node --test` runs the sources unchanged | ES2022 runs on every supported runtime. Erasable syntax lets Node run the sources by type stripping. No option TS 6.0 deprecates, so 7.x compiles it. The declarations spell typed arrays with their buffer type (D6), which TypeScript reads from 5.7 on: the consumer's floor | Adopted |
| D5 | Input arrays | `ArrayLike<number>`: any typed array or a dense `number[]`. A `Float64Array` is read in place; the public tier and `Open` copy every other form into one `Float64Array` on entry | Numerical libraries take typed arrays; JS data (OHLC objects, rows from CSV or JSON) arrives as `number[]`. The copy applies ToNumber, so a `number[]` of numeric strings cannot reach a body where `+` concatenates and `<` compares text. It costs about 1 to 2 ns per bar (intel-1, 2026-11-02): pass a `Float64Array` to skip it | Adopted |
| D6 | Output arrays | `Float64Array<ArrayBuffer>` for real outputs and `Int32Array<ArrayBuffer>` for integer outputs, never `number[]`; the caller may pass each one ([API design](typescript-api-design.md) A7, A8) | Bit-faithful to float64; `Int32Array` matches C `int`; hands off to Arrow and similar with no copy. A `number[]` would grow silently on an out-of-range write | Adopted |
| D7 | Single precision | No `TA_S_` analogue: a `Float32Array` is an `ArrayLike<number>`, widened exactly by the D5 copy. The server serves the float leg's `use_float` by passing the inputs as a `Float32Array` to the same public tier | C's `TA_S_<F>` is bit-identical to `TA_<F>` on the widened doubles, so a widened `Float32Array` is the same contract, and the float leg gates the non-`Float64Array` path | Adopted |
| D8 | Error model | Throw one class, `TALibError extends Error`, with a stable `code` (`'TA_BAD_PARAM'`, ...) that is the contract and a numeric `retCode`. A JS `TypeError` or `RangeError` from misuse is never wrapped. No Result unions | Throwing is idiomatic. A `code` match survives duplicate package copies and realms, where `instanceof` does not. Warm-up is an output range, not an error | Adopted |
| D9 | FMA | Every fused site runs `runtime/fma.ts`'s `fma(a, b, c)`: software, exact, correctly rounded. Sites are chosen by the shared `fma.rs`. A site runs it as a call or, where a body has three or more fused sites (in a batch body, inside loops), as its fast path copied in by the generator from that file, which stays the single swap point | Bit-exactness lets the harness gate TS with no tolerance. Its price is speed: on a loop-carried chain the software `fma` is TS's dominant cost (section 5) | Ruled (owner, 2026-11-01); copy ruled (owner, 2026-11-02) |
| D10 | Integer semantics | Emitted from IR types: a C type pass (`Int32`, `Real`, `Bool`) over every expression. An integer `/`, an integer `%` and every real-to-int conversion, explicit or implicit, truncate with `\| 0`. Generation fails on any expression it cannot type | JS has no integer type, and a wrong guess fails silently | Ruled (owner, 2026-11-01) |
| D11 | Transcendental functions | The JS engine's `Math.*`. A call that reaches one (the function carries `uses_transcendental`, or an MA-type parameter selects MAMA or ALMA) compares in the transcendental lane at 1e-11, held in one constant and scaled like Java's 1e-9 (relative above magnitude 1, absolute below). Every other call, and same-language stream against batch, stays bitwise. A deviation above 1e-11 goes to the owner; never widen the constant without a ruling | `Math.*` is neither correctly rounded nor glibc: Node 22 against glibc 2.40 measured at most 2 ULP per call, which ill-conditioned functions amplify (KSTEXT, MAMA, SWAK_BP, the largest near 1e-11). With glibc's result substituted for every `Math.*` call, TS equals C bitwise. Such a call can differ between JS engines and engine versions. HT_DCPHASE and HT_SINE have no tolerance-sized bound in any language on input flat for a whole dominant cycle: the cycle sums are cancellation noise, so a 1-ulp `sin` or `cos` difference can flip the phase quadrant | Ruled (owner, 2026-11-01) |
| D12 | Function shape and settings | One ES module per function, exporting free functions. The `core` option carries unstable periods and candle settings. `Core` is immutable, built by `CoreBuilder`, and frozen with its settings and every exported enum and flag object. A stream captures its `Core` at open | Tree-shakable; keeps the Java and C# `Core`/`CoreBuilder` words | Adopted |
| D13 | Optional parameters | Keys of the options object ([API design](typescript-api-design.md) A3, A9). An omitted key, `Core.INTEGER_DEFAULT` or `Core.REAL_DEFAULT` selects the default. Enum parameters are typed as the enum's literal union plus the integer sentinel. An integer parameter is rejected unless it passes `Number.isInteger` and fits int32, and a real one unless it is a number | The metadata tier maps 1:1 onto the `<n>Positional` form | Adopted |
| D14 | Allocating form | None apart: the one public form allocates each output buffer left out (API design A8) | One public batch tier, the one the harness gates | Adopted |
| D15 | Streaming handle | Class `<N>Stream`, returned by `<n>Open` and, beside the batch result over the history, by `<n>OpenAndFill`, with `update`, `peek`, `value`, `outRange`, `advance` and `clone`. A single-output function returns a `number`; a multi-output one a `<N>Out`, the caller's sink when one is passed. No `close()` | Garbage collection frees the handle. A passed sink avoids an allocation per bar, as in Java | Adopted |
| D16 | Naming and tiers | Java casing: functions lowerCamel, types UpperCamel. `<n>Impl`, `<n>OpenInternal`, `<n>OpenAndFillInternal`, the `<n>Positional` family (`<n>Positional`, `<n>LookbackPositional`, `<n>DisplayShiftPositional`, `<n>OpenPositional`, `<n>OpenAndFillPositional`) and the tape frames (`<n>StepTape`, `<n>PeekTape`, `<n>TapeDetach`) are exported from their module, tagged `@internal`, and absent from the package barrel. `<n>OpenImpl` and `<n>StepImpl` stay module-local. Handle state fields are public and `@internal` | The CLAUDE.md vocabulary recast; the `exports` map plus an explicit barrel is TS's package-private. The fields are public so the module-local frames reach them | Adopted |
| D17 | Backend id | `--backend=ts`, `--language=ts`, label `TypeScript`, release tag `ts-v<version>` | The `java-v` / `rust-v` / `csharp-v` pattern | Adopted |
| D18 | Metadata API | Subpath `./metadata` with `Functions.byName` / `all` / `groups`, `ParamHolder` (`setInput`, `setPriceInput`, `setOptInput`, `setOutput`, `lookback`, `displayShift`, `call`), `FuncInfo`, the flags, `FunctionDescription` and `getRuntimeInfo`. Each row carries the typed call's `key` beside C's name (the positional input name, the rJ1 option key, the result key), and `setOptInput` takes a parameter's key as well as its position (rJ6). `call` invokes `<n>Positional`, with the typed tier's range defaults when its arguments are omitted (API design A6): `startIdx` 0, `endIdx` the last bar of the first bound input, of its first consumed component for a price input. | D21 | Toolchain | Building and testing need Node `>=22.18` and npm; a JavaScript consumer needs only D3's floor, a TypeScript consumer D4's too (5.7) | Type stripping is on by default from 22.18, so `node --test` runs the `.ts` tests | Adopted |

Package layout under `ta_codegen/output/ts/` (D20):

- **Tooling root:** a private `package.json` with no workspaces (devDependencies `typescript` and `@types/node`, the latter at the lowest supported Node major) and `package-lock.json`. Only the tools and test tsconfigs list `node` in `types`, so the library compiles with no Node types.
- **`library/`:** the published package. `dist/` is emitted twice: the JavaScript with `removeComments`, so only the `/*!` licence block each source opens with stays, and the declarations apart, with their TSDoc (D19); `build-libraries` and `ts_package_check.py` both build it so and fail unless every `.js` opens with the licence and holds no other comment and every function's `.d.ts` keeps its TSDoc. Generated: `package.json` (version from `VERSION`), `src/func/<lowerCamel>.ts`, `src/index.ts` (explicit export lists), `src/enums.ts`, `src/metadata/`, `test/gen/`, which `generate` owns whole, `test/phantomIo.test.ts` (H14) and a copy of `LICENSE`. Hand-written: `src/runtime/`, the rest of `test/`, `README.md`.
- **`tools/`:** the generated server, with the fuzz port spliced in, and a tsconfig that compiles `../library/src`.
- **No bench package:** `ta_bench` times the server's `timed` path.

## 3. Numerical semantics

Semantics come from the type pass, never from a name heuristic. FMA site selection is the one exception: it calls `fma.rs` exactly as Java and C# do, heuristics included, because the fused sites must match C's.

| # | Hazard | Where | Emitter rule | Gate that catches it |
|---|---|---|---|---|
| H1 | Untyped expression | Any body | Generation fails | `generate` (loud) |
| H2 | Integer `/` yields a fraction | Lookbacks, auto-stabilization rules, median midpoints, DPO, ZLEMA, HMA, ... | `((a) / (b)) \| 0`. Compound `i /= k` expands to `i = ((i) / (k)) \| 0` | `ts_int_semantics_suite`; a lookback mismatch in `--codegen` |
| H3 | Integer `%` yields -0 | `today % 2` (HT family, MAMA), FRAMA, TRIMA, PERCENTILE | `((a) % (b)) \| 0` | `ts_int_semantics_suite` |
| H4 | Real to int, explicit or implicit | `(int)ceil`, `(int)floor`, `(int)sqrt`, `(int)DCPeriod`, the MAVP period; implicit at an int local, int return or int argument, on which `gcc` does not warn | `(x) \| 0`, which truncates and clears -0. Never `Math.trunc` alone, which keeps -0. The corpus's clamps keep the value in range | `ts_int_semantics_suite`; the HT stream legs |
| H5 | Integer -0 leaking into real arithmetic | Integer `Neg`, `Mul`, `Mod`, and any integer produced from a real | Wrap each such producer in `\| 0`. Integer outputs, rings and scratch are `Int32Array` | `ts_int_semantics_suite`; xlang-hash raw bits (reached sites only) |
| H6 | Bool used as a number, or a number tested for truth | Candle helpers, `!ptr`, `!TA_IS_ZERO` | A Bool used as a value becomes `(c ? 1 : 0)`; a non-Bool condition gets an explicit `!== 0` | `tsc --strict`; an assert in the type pass |
| H7 | Real max/min | `max(`/`min(`, `fmin`/`fmax` in the candle helpers, running extremes | `a > b ? a : b` and `a < b ? a : b`, in C's operand order. `Math.max` and `Math.min` differ from C on NaN and on ±0 | Text gate in `ts_render_statement_suite`: no `Math.max(`, `Math.min(`, `Math.round(` or `>>>` in library output |
| H8 | Shifts and masks | TRIMA `>> 1`, `& (live-1)` | As written: JS bit operations are int32, like C `int` | Same text gate |
| H9 | Fused-site selection | Every site C fuses | `fma.rs`'s selection, called where Java's emitter calls it. C's compound rule: `x += a*b` is not fused, `x = x + a*b` is | xlang-hash and server_verify, bitwise |
| H10 | Stream and batch fuse different sites | Stream step and peek bodies | State and output names keep the `sp.` / `cur_` prefixes that `fma::stream_base` strips | stream_verify same-tier, bitwise |
| H11 | Software fma rounding | `runtime/fma.ts` | Exact and correctly rounded (D9) | `ts_fma_check.py`, then xlang-hash on every fusing function |
| H12 | Transcendental results | Flagged functions; MAMA or ALMA through an MA-type parameter | Engine `Math.*` | The transcendental lane at 1e-11 (D11) |
| H13 | Literal text | Every real literal | Shortest round-trip text, never a fixed precision | xlang-hash |
| H14 | Out-of-bounds typed-array access | Every body | The public tier checks every length before `<n>Impl`. A read past the end gives `undefined` and a write is dropped, both silently | Generated phantom-I/O sweep with Proxy-guarded arrays that throw on an out-of-range index and range-check `set`, `subarray`, `fill` and `copyWithin`; checked typed arrays under `--codegen` and `--xlang-hash` (nightly); `out_tail_dirty` for writes into the slack |
| H15 | Aliasing views | The batch and OpenAndFill guards; C's `inReal == outReal` scratch election | Overlap means the same `buffer` with intersecting byte ranges, and C pointer equality the same `buffer` and `byteOffset`; never `===`. Batch rejects two outputs that share memory and an output that partly overlaps a `Float64Array` input; the output may be that input in place (same `buffer`, `byteOffset` and `length`). OpenAndFill rejects any overlap with an input | stream_verify aliasing rejects; library tests with `subarray` views |
| H16 | Non-`Float64Array` inputs | Public tier, `Open` | Copy into a `Float64Array` on entry (D5) | The float leg; library test: a `number[]` of numbers and one of numeric strings give the `Float64Array` bits on every function |
| H17 | Non-integer or out-of-int32 integer parameter; non-number real parameter | Public tier, `Open` | Reject before the range checks, keeping the `INT_MIN` and `-4e37` sentinels; the lookback answers -1 | Library test; `open_validation_suite` |
| H18 | Bit access on a big-endian host | The fma helper, the server codec | `DataView` with explicit endianness | `ts_fma_check.py`; server_verify |

**Structural gate.** `ts_int_semantics_suite` takes its verdict from the type pass the emitter uses. After changing either, prove it red both ways: drop `| 0` from the emitter's integer-division arm, then force one real division (SMA's `sum / period`) to `Int32` in the type pass; each must fail.

## 4. Silent traps

- **Stale library.** `build.py servers` regenerates only the servers, then compiles the TS server over whatever `library/src` holds. After editing an input `.c` or a generator module, run `build.py generate` first, or every gate passes on old code.
- **Peek writes.** A peek that stores where the next update overwrites before any read (the incoming bar's ring or tape slot, a scratch field) passes every value gate. The `managed_stream_suite` no-write sweeps are the whole gate.
- **Lockfile.** Keep the tooling root without workspaces and the library without dependencies, so the lockfile never records the library version and `sync.py` never churns it.

## 5. Performance

Measured on intel-1 and amd-1 (2026-11-02), every function, batch, TypeScript timed through the body:

- Median 150% to 240% slower than C at 2000 and 100k bars; 65% to 135% slower than Java.
- Software `fma` (D9) is the dominant cost: every function more than 400% slower than Java runs it on a loop-carried chain. T3 is the worst, 1669% slower than Java on intel-1 at 100k bars (3,160,190 ns vs 178,671 ns).
