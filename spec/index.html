Specification

TA-Lib's calling contract, stated rule by rule for a robust integration. Every rule is enforced by the test suite, so your code can rely on it.

Written as a reference for AI agents integrating TA-Lib. For a lighter introduction written for people, start with the API pages for C/C++, Rust, Java or C#.

The rules cover the four native APIs (C, Rust, Java, C#). Each rule has one home page, states what the code does, and is written in C's spelling. This page maps that shared vocabulary onto Rust, Java and C#; a rule that introduces a language-specific name gives all four spellings itself.

Scope

  • The four native APIs: batch, lookback, display shift, streams, settings, and the abstraction layer, which is specified only in part (rM1).
  • A wrapper keeps its own conventions. ta-lib-python aligns outputs to the input and fills the warm-up with NaN; the native APIs do not (rW3).
  • Published packages and their versions: Install.
  • Owned by other pages: Unstable Period, Candlestick Settings (model and defaults), streaming in C, Rust, Java and C#, Numerical Stability, and the function pages: inputs, outputs in order, parameters (type, default, accepted values), stability category, flags.
  • Every page except the per-function pages in one file: /llms-full.txt, whose function index lists and links each function's page; /llms.txt indexes them all. Each page has a Markdown twin, /spec/index.md for this one.

Each page has two kinds of statement:

  • The caller must: what the calling code has to ensure. Most of it is not checked by the library, so it comes first on every page, and the next section collects the items that fail silently.
  • A rule: what TA-Lib does. Every rule is enforced by the test suite. Its id is r, the letter of its family and a number, such as rB5, and its anchor is the id in lower case: /spec/errors/#rb5. An id's meaning can change from one release to the next.

<N> stands for a function's canonical name: TA_<N>_Open is TA_SMA_Open.

What is not detected

None of these is reported. The caller avoids them, or treats what follows as undefined.

  • A buffer too short, in C: read or written past its end. Rust, Java and C# reject it.
  • NaN or infinity inside an input series, or inside the history a stream opens on.
  • A real input outside ±3e37.
  • Intermediate overflow on finite input.
  • Buffers that partially overlap, in C.
  • C used before TA_Initialize or after TA_Shutdown, or TA_Initialize called twice.
  • A C setting changed while a TA function is running or a stream is open.
  • A writer and any other call at once on one stream handle, or two threads on one parameter holder or builder (in Rust, the compiler rejects it).
  • C's unstable-period getter given a wildcard or unknown id: it returns 0.
  • The state after an allocation failure.
